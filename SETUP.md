# Environment Setup (lab / remote machine)

How to reproduce this project on a fresh machine after cloning. The environment
has **two parts**:

1. A **host Python venv** (`requirements.txt`) for geometry, meshing, dataset, viz,
   and the ANSYS cross-validation tools.
2. The **`dolfinx/dolfinx:stable` Docker image** for the FEniCSx modal FEM solve.
   dolfinx / PETSc / MPI are intentionally *not* in the host venv.

## Prerequisites

- **Git**
- **Python 3.12** (the venv was built with 3.12.3). `python3.12 --version` should work.
- **Docker** (the FEM solve runs in a container; verify with `docker run --rm hello-world`).
- Linux is assumed (the solver image and venv are Linux). On Windows, run everything
  from WSL2.

## 1. Clone

```bash
git clone https://github.com/GijeongPark/diffusion.git
cd diffusion
```

## 2. Host Python environment

```bash
python3.12 -m venv .venv
./.venv/bin/pip install --upgrade pip
./.venv/bin/pip install -r requirements.txt
```

The repo is run *from its root* — the `peh_inverse_design` package is imported
directly (no `pip install -e .` needed). API entry point:
`from peh_inverse_design import PipelineConfig, run_pipeline`.

## 3. FEM solver Docker image

```bash
docker pull dolfinx/dolfinx:stable
```

The solver is invoked automatically by the pipeline, or manually:

```bash
./scripts/run_fenicsx_solver.sh \
  --mesh /workspace/meshes/volumes/plate3d_0000_fenicsx.npz \
  --response-dir /workspace/data/fem_responses \
  --modes-dir /workspace/data/modal_data
```

> The image tag is the mutable `:stable`. For a *reproducible* run, pin a specific
> dolfinx release tag and set it via the `FENICSX_IMAGE` env var (used by
> `scripts/run_fenicsx_solver.sh`) or `--docker-image` (used by `pipeline_runner`).

## 4. Input dataset

`data/unit_cell_dataset.npz` is committed and is the pipeline's input. Everything
else under `data/`, plus `meshes/` and `runs/`, is **generated output** and is
git-ignored — it is regenerated by running the pipeline. To produce a fresh
unit-cell dataset instead, run `1 periodic_grf_sdf.ipynb`.

## 5. Quick test run (3 samples)

```bash
# carve a 3-sample subset
./.venv/bin/python -m peh_inverse_design.datasets.subset_unit_cell_dataset \
  --input data/unit_cell_dataset.npz \
  --output data/test_runs/test3/unit_cell_dataset.npz \
  --limit 3

# run the full pipeline into runs/test3/
bash scripts/run_all.sh \
  --unit-cell-npz data/test_runs/test3/unit_cell_dataset.npz \
  --limit 3 \
  --run-name test3
```

Outputs land under `runs/test3/` (meshes, FEM responses, modal data, the integrated
dataset, and report images). If step 1 fails, inspect
`runs/test3/meshes/volumes/mesh_build_summary.json` for CAD rejection reasons.

## Notebook workflow

`2 integrated_peh_pipeline.ipynb` drives the same pipeline. Material and physical
properties are edited in its **② Materials & physics** cell, assembled into
`PROBLEM_SPEC`, which overrides `configs/peh_inverse_design_spec.yaml`.

```bash
./.venv/bin/python -m jupyterlab
```
